# [개발일지 #8] 내보낼 때 AI 보정 — 실제 쇼츠로 재 보기

> 2026-11-10 · Python 3.12 · PySide6 6.12

## 샘플 쇼츠 테스트 마무리

어제 시작한 테스트를 끝냈다. CapCut으로 만든 54.8초 세로 쇼츠를 원본(4K 60fps HEVC 81.5초)에서 KS Studio 기능만으로 다시 만드는 테스트다. AI 보정은 두 방식으로 같은 결과물을 만들어 비교했다.

- **예전 방식:** 원본 전체를 원본 크기로 보정한 파일을 만든 뒤, 그 파일로 다시 잘라 내보낸다.
- **새 방식:** 어제 바꾼 방식이다. 내보낼 때 타임라인이 쓰는 프레임에만, 내보낼 크기로 보정을 입힌다.

### 걸린 시간 (개발 PC)

| | 예전 방식 | 새 방식 |
|---|---|---|
| 얼굴 분석 | 영상 전체 250초 | 쓰는 구간만 약 3분 |
| 보정 | 4K로 원본 전체 1,890초 | 1080p로 쓰는 1,645장 (내보내기 안에서) |
| 내보내기 | 358초 | 분석 포함 867초 |
| **합계** | **약 41분 40초** | **약 14분 30초** |

새 방식이 2.9배 빠르다. 결과도 거의 같다. 같은 시각 프레임끼리 비교한 PSNR이 중앙값 41.9dB, 가장 낮은 곳 33.6dB다. 얼굴~허리를 크게 잘라 나란히 놓아 봐도 차이가 눈에 띄지 않는다.

새 방식은 처음 상태에서 쟀다. 예전 방식이 만들어 둔 영상 전체 얼굴 분석 파일을 잠깐 치워서, 쓰는 구간만 분석하는 시간이 그대로 잡히게 했다. 한 번 분석한 구간은 캐시에 남으므로, 다시 내보낼 때는 약 11분 반이다.

### 새 방식에서 시간이 드는 곳

1080p 한 프레임을 단계별로 쟀다.

| 단계 | 시간 |
|---|---|
| 몸 변형 + 드러난 배경 메꾸기 (허리 · 얼굴 작게) | 161 ms |
| 몸 분리 + 몸의 점 찾기 | 57 ms |
| 얼굴 보정 (피부 · 눈 · 갸름) | 14 ms |
| 4K 디코딩 · 1080p로 줄이기 | 6 ms |

**몸매 보정이 보정 시간의 약 88%**다. 얼굴 보정만 켜면 몇 분이면 끝날 것으로 본다. 몸 분리와 배경 메꾸기를 몇 프레임마다 하거나 더 작게 하는 방법을 다음에 본다 (TODO).

### 함께 찾은 것: 4K 원본은 색 보정 때문에 내보내기가 느리다

예전 방식 내보내기는 보정 없이도 358초 걸렸다 (54.8초 영상). 원인은 색 보정(LUT)이다. 지금은 4K 원본 크기 그대로 색 보정을 입힌 뒤에 1080p로 줄인다. 새 방식은 보정 때문에 먼저 1080p로 줄이므로 색 보정도 작은 화면에 입힌다. 보정이 없는 영상도 "먼저 줄이고 색 보정"으로 바꾸면 빨라질 것이다 (TODO).

### 목표 영상과 비교

- **컷 · 글자 · 색:** 거의 같다.
- **글자 모양:** 글꼴이 조금 가늘다 (Pretendard Black이 없다). 노란 상자는 조금 작고, 엔딩 요약표 칸 크기가 제각각이다.
- **보정:** 얼굴은 비슷하다. 목표 쪽 몸이 조금 더 가늘다. CapCut의 '몸'·'머리' 칸이 KS에는 없다.
- **소리:** 결과가 더 크다 (RMS −18.9dB vs 목표 −26.0dB). 소리 크기 맞추기(−14 LUFS)를 켰기 때문이다. 0.7초 효과음은 빠졌다 (파일 없음).

수정점 12개에 우선순위를 매겨 `docs/TODO.md`에 옮겼다. 위에서부터 글자 복제·목록 글자, 글자 왼쪽 맞추기, 몸매 보정 속도, 색 보정을 줄인 뒤에 입히기 순이다.

### 비교 도구

샘플 테스트 스크립트에 단계 셋을 더했다.

- `beauty_file`: 예전 방식 보정본 파일 만들기
- `old`: 그 파일로 잘라 내보내기
- `beauty_compare`: 같은 장면의 얼굴~허리를 보정 없음 · 예전 · 새 방식으로 나란히 놓는다

처음에는 "보정 없음" 칸을 원본 파일에서 시각으로 찾았는데, 장면이 어긋났다. 같은 타임라인을 보정 없이 그린 장면으로 바꿨다.

## 하이라이트 분할 5단계 — 나눈 뒤에 이어 할 일

✨ 하이라이트 분할 버튼 옆 ▾ 메뉴에 세 가지를 넣었다. 분할을 한 번 눌러 점수가 생긴 뒤에만 누를 수 있다.

- **하이라이트만 남기기:** 초록 띠(클립의 절반 이상이 하이라이트)가 아닌 V1 컷을 지우고 뒤를 당긴다. 연동을 켰으면 위 줄도 그 장면을 따라 정리된다.
- **점수 낮은 컷 지우기…:** 기준 점수(처음 30점)를 고르는 창이 뜬다. 슬라이더를 움직이면 "30점보다 낮은 컷 5개 · 52.7초를 지웁니다"처럼 지워질 양이 바로 보이고, 지금 컷 점수들도 같이 보인다. 지울 컷이 없으면 [지우기]가 꺼진다.
- **하이라이트 컷 모두 선택:** 복사·복제·속성 바꾸기를 한 번에 하려고.
- 점수가 없는 V1 컷(분석하지 않은 영상)은 고르지도 지우지도 않는다. 그런 컷이 있으면 알림에 몇 개인지 적는다.
- 지우기는 Ctrl+Z 한 번으로 돌아온다.

계산(어느 컷이 하이라이트인지, 기준보다 낮은지)은 `core/highlight_cuts.py`에 화면과 상관없는 함수로 두고, 화면은 그 결과로 지우기·선택만 한다.

**확인:** 실제 촬영본 2개(37초 1080p · 45초 4K60)로 해 봤다.
- 분할하면 컷 8개가 나왔다. 컷 점수는 25 · 38 · 27 · 26 · 56 · 13 · 45 · 9였다.
- 하이라이트 컷 모두 선택 → 3개 (29.2초).
- 하이라이트만 남기기 → 5개 · 52.7초를 지우고 3개만 남았다.
- Ctrl+Z → 8개로 돌아왔다.
- 30점보다 낮은 컷 지우기 → 5개를 지웠다.

테스트 4개를 더했다 (하이라이트·나머지 컷 고르기, 낮은 컷·평균, 메뉴 동작·되돌리기, 기준 창).

## AI 보정 값을 목표 영상에 맞추기

샘플 쇼츠를 다시 편집했다. 어제는 CapCut 보정 숫자를 KS 칸에 그대로 옮겼는데, 두 프로그램의 세기가 같다는 근거가 없었다. 결과도 콧볼·눈이 목표와 반대 방향이었다. 그래서 목표 영상과 같은 장면 5곳을 재서 맞췄다.

- **재는 것:**
  - 얼굴 106점으로: 눈 사이 거리(얼굴 크기) · 아래턱 · 볼 · 콧볼 폭 · 눈 크기 · 얼굴 길이
  - 볼 피부: 밝기 · 광택 · 거칠기 · 붉기 · 노랑 — 목표 해상도 406×720으로 줄여서 같은 조건으로
  - 벽: 밝기 · 노랑
  - 허리 폭: 사람 분리 + 어깨·골반 점
- **목표 − 보정 없음:**
  - 얼굴: 콧볼 −10.8% · 아래턱 −3.4% · 볼 −2.7% · 얼굴 길이 −2.5% · 눈 +2.7% · 눈 사이 +0.3%
  - 피부: 밝기 −5.7 · 붉기 +3.9 · 노랑 −6.0
  - 벽: 밝기 +1.7 · 노랑 −2.5
- 칸마다 값을 바꿔 가며 같은 양이 나오는 값을 찾았다.
  - 콧볼 축소 1.0 · 얼굴 갸름 0.65 · 턱 −0.7 · 눈 0.5 · 블러셔 0.8 · 매끈하게 0.5 · 얼굴 작게 0 · 밝게 0
  - 색: 색온도 −0.3 · 노출 +0.02
- **배운 것:**
  - CapCut "작은 얼굴 0.13"은 얼굴 전체를 줄이지 않았다 (눈 사이 거리가 그대로).
  - "베이비 핑크" 메이크업은 KS 블러셔와 비슷하게 볼을 붉고 조금 어둡게 했다.
  - 색온도는 CapCut −0.154 = KS −0.3쯤이다.
- **결과 (같은 경로로 그린 장면에서):** 콧볼 −8.2% · 눈 +2.6% · 얼굴 길이 −2.4% · 피부 붉기 +3.4% · 벽 노랑 −2.3%. 어제 값은 콧볼 −2.5% · 눈 −1.5%였다.
- **남은 차이:** 콧볼 축소를 최대로 해도 목표에 못 미친다. 피부 노란 기를 뺄 칸이 없다 → TODO 10-1.
- 내보내기는 522초 (얼굴 분석은 캐시 · 얼굴 작게를 꺼서 몸 분리가 허리 하나만).

## 콧볼 축소 최대치 · 팔자주름 지우기

### 콧볼 축소: 100% = 목표 수준

샘플 쇼츠를 맞추다 보니 콧볼 축소를 최대로 해도 콧볼 폭이 −6.3%만 줄었다 (CapCut으로 만든 목표는 −10.7%). 세 가지를 같은 장면 5곳에서 재 봤다.

| 방식 | 콧볼 폭 (100%) |
|---|---|
| 지금: 콧볼 가운데 한 점을 코 가운데 쪽으로 30% | −6.3% |
| 같은 한 점을 50% | **−10.6%** |
| 콧볼 여섯 점을 코 가운데 선 쪽으로 45% | −10.3% |

여러 점을 당겨도 더 낫지 않았고, 확대해 봐도 코 모양은 둘 다 자연스러웠다. 그래서 가장 단순하게 최대치만 0.3 → 0.5로 올렸다. 이미 콧볼 축소를 써 둔 영상은 다시 내보내면 코가 조금 더 좁아진다 (전 100% ≈ 지금 60%) — 패치노트에 적었다.

### 팔자주름 지우기 (AI 보정 › 피부)

콧볼 바깥에서 입꼬리 바깥 아래까지 양쪽에 가는 띠를 얼굴 점으로 잡는다. 그 안에서 **주변보다 어두운 만큼(그늘)만** 밝힌다. 매끈하게처럼 흐리면 그 자리만 플라스틱처럼 보이기 때문이다.

- **그늘 재기:** 잔결(1~2px)만 지운 밝기와 "주름보다 넓은 골짜기를 메운 밝은 윤곽"(모폴로지 닫힘)의 차. 처음에는 넓게 흐린 평균을 썼는데, 주름 자체의 어두움이 평균에 섞여 그늘을 70%만 찾았다 (가짜 주름 28 → 8).
- **색:** 그늘진 곳은 조금 붉고 탁해서, 그늘 진하기만큼 주변 피부색 쪽으로 옮긴다.
- **세기:** 슬라이더에 비례한다. 가짜 주름으로 잰 지워진 양이 25% → 21%, 50% → 46%, 75% → 68%, **100% → 93%**다. 사용자 의견대로 100%를 "거의 다"로 두고, 자연스러운 정도(70~80%)는 슬라이더를 덜 올려서 고른다. 툴팁에 "자연스럽게는 60~80%"라고 적었다.
- 띠는 처음보다 넓고(반폭 0.07 → 0.09) 길게(1.3배) 했다. 타원은 끝으로 갈수록 약해져서 콧볼·입꼬리 쪽이 덜 지워졌다.
- **실제 촬영본:** 웃는 장면의 팔자가 걷히고, 테두리·얼룩은 보이지 않았다. 띠 안 그늘(측정값)은 100%에서 −0.30이었다.
- 측정하다 보니 콧볼 축소만 켜도 "팔자 그늘"이 +0.5 늘었다. 순서를 바꿔(변형 뒤에 팔자 지우기) 재 봐도 같았다. 콧볼이 좁아지면 측정 띠가 안쪽으로 따라 들어가 원래 있던 콧볼 옆 그늘을 같이 재는 착시였다. 순서는 그대로 두었다.

**샘플 쇼츠 다시 내보내기:** 콧볼 100% · 팔자주름 100%를 더해 539초. 얼굴 비교 그림에서 앞 결과보다 코가 좁아지고, 웃는 장면의 팔자가 옅어졌다.
